# 2차 작업 브리프 (팀장)

## 1. 의뢰인 피드백 (원문)

> 중간중간에 이거 무슨 뜻이지? 하는 부분이 많아. 그런 경험적인 측면을 다듬어줘.
> 아직 실제 스팀 게임만큼의 재미가 없어. 게임 흐름이나 기믹들을 좀 다듬어줘.

의뢰인은 1차 기획서(Word, 92쪽)와 프로토타입(/home/claude/proto/index.html, 웹 단일 파일)을 봤다.

## 2. 팀장 해석

1. "이거 무슨 뜻이지?"는 두 곳에서 생긴다.
   - 게임 안: 처음 하는 사람이 화면 요소, 숫자, 아이콘, 계단 종류, 분필 X/O, 두드려 보기, 초, 상점 문구, 정산 결과 등의 의미를 바로 알지 못하는 순간. 규칙이 왜 그렇게 됐는지(왜 체력이 깎였는지, 왜 계단이 안 내려가지는지 등) 화면이 알려 주지 않는 순간.
   - 문서 안: H01, D18, B3, T2, I30 같은 내부 코드, '체비쇼프 거리' 같은 전문 용어, 설명 없이 쓴 약어. 문서를 읽는 사람이 플레이 장면을 떠올리기 어렵다.
   2차의 1순위는 게임 안의 혼란이다. 문서는 그 다음.
2. "스팀 게임만큼의 재미가 없다"는 수치 조정으로 해결되지 않는다. 한 판 안에서 손에 잡히는 재미의 순간(긴장, 보상, 과감한 선택, 조합이 터지는 쾌감, 예상 못 한 사건)이 부족하다는 뜻으로 본다. 흐름(하루·층·30일의 리듬)과 기믹(규칙을 비트는 장치)을 다시 본다.

## 3. 2차 원칙

- 지켜야 할 것: 지뢰찾기 숫자 추리 + 채굴 + 로그라이트, "숫자에 지뢰와 보물이 함께 섞여 있음", 초(촛불) 자원, 탑다운 픽셀(시안 A), 1인 개발 규모, 의뢰인 문서 선호(이모지 금지, 짧은 문장, AI 티 나는 대구 문장 금지).
- 바꿔도 되는 것: 30일 길이, 하루·층 구조, 목표 금액 방식, 상점 구조, 도구 체계, 계단 종류, 이벤트, 숫자 외의 기믹. 단 바꾸면 이유를 '플레이어가 느끼는 것' 기준으로 적는다.
- 판단 기준: "처음 하는 사람이 설명 없이 3분 안에 하고 싶은 행동을 찾는가", "10분 안에 '와' 하는 순간이 있는가", "한 판이 끝나면 한 판 더 하고 싶은가".
