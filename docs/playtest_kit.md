# 플레이테스트 안내 (재미 보고서 4주차)

재미 보고서(reviews/12_fun_report.html) 7장의 위험 세 가지를 사람 5명으로 확인하는 안내서예요. 봇은 이미 쟀고(05 8.11~8.13), 이 시험은 봇이 못 재는 것(하루 길이, 걸기의 맛, 갈림길에서 고르는 이유, 두 번째 판을 시작하는지)을 봐요.

## 1. 준비

| 항목 | 내용 |
|---|---|
| 빌드 | `cd prototype && npm run build` 뒤 `dist/index.html`을 테스터에게 보내거나 정적 호스팅에 올려요. 개발 서버(`npm run dev`)여도 돼요 |
| 규칙 | 기본은 v2.2 시험 규칙이에요. 비교가 필요하면 주소 뒤에 `?preset=v21`을 붙여 2차 기획 v2.1 규칙으로 해 볼 수 있어요. 설정 창 맨 아래에 지금 규칙이 적혀 있어요 |
| 기록 | 따로 켤 것이 없어요. 하루가 끝날 때마다 브라우저에 한 줄씩 쌓여요(09 C.3.1) |
| 사람 | 5명. 지뢰찾기를 해 본 사람 3명, 거의 안 해 본 사람 2명이 좋아요 |
| 시간 | 한 사람 40~60분 |

테스터 브라우저가 처음이면 첫 판 안내(오프닝 만화 → 첫날 정해진 층)로 시작해요. 같은 브라우저를 여러 사람이 쓰면 설정 창의 '플레이 기록 지우기'로 비우고, 설정 저장소도 비워야 첫 판 안내가 다시 나와요.

## 2. 진행

1. 규칙 설명 없이 시작해요. "이 게임은 처음이에요. 생각나는 대로 말하면서 해 주세요" 한 줄만 말해요.
2. 첫 도장(3일째)까지는 질문에 답하지 않아요. 막히면 어디서 막혔는지 적어요.
3. 3일째 뒤로는 테스터가 그만두고 싶을 때까지 해요. 그만두는 순간과 이유를 적어요.
4. 판이 끝나면(해지든 완납이든) **아무 말도 하지 않고** 30초 기다려요. 두 번째 판을 스스로 시작하는지 봐요.
5. 끝나면 설정 → '플레이 기록 내려받기'로 JSON 파일을 받아요. 파일 이름에 테스터 번호를 붙여요.
6. 아래 질문을 해요.

## 3. 질문

| 번호 | 질문 | 보는 것 |
|---|---|---|
| 1 | 가장 재미있던 순간 하나를 말해 주세요 | 세 순간(광맥으로 보물 확정 → 줄, 마지막 한 칸 걸기, 확신한 지뢰 발파) 가운데 무엇인가 |
| 2 | 가장 지루하던 순간 하나를 말해 주세요 | 계단 찾기, 안전한 칸 캐기, 상점, 기다리는 연출 |
| 3 | 갈림길에서 카드를 어떻게 골랐어요? | '새로워서' 말고 다른 이유(줄, 발파, 덩이, 보물 수)가 나오는가 |
| 4 | 지뢰를 밟았을 때 판 아래 한 줄을 봤어요? 억울했어요? | 지뢰 판정 한 줄이 읽히는가 |
| 5 | 도장 선물에서 도구와 금고 돈 중 무엇을 골랐고 왜요? | 도구 대 돈이 진짜 고민인가 |
| 6 | 둘레 한꺼번에 열기를 썼어요? 언제요? | 발견했는가, 손맛이 있는가 |
| 7 | 오늘의 광산이나 다음 등급을 해 보고 싶어요? | 판 밖 동기 |
| 8 | 뜻을 몰라서 멈춘 말이 있었어요? 마우스를 올려 설명을 봤어요? | 화면 용어와 용어 설명이 통하는가 |
| 9 | 더 깊이 내려가고 싶었던 이유, 안 내려간 이유는요? | 깊이의 보상이 읽히는가 |

## 4. 판정 기준(보고서 7장)

| 위험 | 통과 | 실패 | 어디서 보나 |
|---|---|---|---|
| 하루 리듬과 결정 밀도 | 하루 중앙값 3~5분, 1분에 결과를 모르고 고른 수 1회 이상 | 하루 7분 초과, 또는 1분에 0.5회 미만 | 기록 JSON의 `ms`, `uncertain`. 설정 창 요약 한 줄 |
| 광맥 3종의 다양성과 갈림길의 의미 | 5명 중 4명이 '새로워서' 말고 다른 이유로 골라요. 봇 기준 광맥별 Day 9~14 수입이 ±15% 안(05 8.12에서 통과) | 한 광맥을 사람 70% 넘게 골라요 | 질문 3, 기록 JSON에는 광맥 선택이 없어 관찰 기록으로 |
| 처음 하는 사람의 경제 | 사람 실패가 첫 두 도장에 몰리지 않아요. 5명 중 3명이 권하지 않아도 두 번째 판을 시작해요 | 사람 실패의 절반 이상이 첫 두 도장에서 나와요 | 진행 4번, 기록 JSON의 `stamps`와 `day` |

## 5. 기록 JSON 읽는 법

한 줄이 하루예요. 주요 값만 적어요(전체는 09 C.3.1).

| 값 | 뜻 |
|---|---|
| `ms` | 하루 걸린 시간(밀리초). 60000이 1분 |
| `clicks` | 판 클릭 수(왼쪽 + 오른쪽) |
| `uncertain` | 결과를 모르고 고른 수(보물 아니면 지뢰인 칸 치기 + 모르는 칸 치기 + 확실하지 않은 발파) |
| `reason` | 하루가 끝난 이유. `return` 올라가기, `collapse` 쓰러짐, `candle` 촛불이 다 탐 |
| `rec.chords` | 둘레 한꺼번에 열기를 쓴 횟수 |
| `stamps` | 그날 밤까지 찍은 도장 수 |

5명의 파일을 모아 하루 시간 중앙값과 1분당 `uncertain`을 구해요. 스프레드시트로 열어도 되고, Node로 몇 줄이면 돼요.

## 6. 결과를 받은 뒤

| 결과 | 할 일 |
|---|---|
| 하루가 7분을 넘어요 | 촛불을 80 → 60~70으로 줄이는 안을 봇으로 재요 |
| 1분에 고른 수가 0.5회 미만 | 기록의 `rec.chords`로 둘레 한꺼번에 열기를 많이 쓴 사람과 거의 안 쓴 사람을 비교해요. 안전한 칸 치기가 너무 많으면 큰 와르르 자갈 기준(8칸)을 낮춰 보상을 걸기 쪽으로 옮겨요 |
| 처음 하는 사람이 3·4번째 도장에서 대부분 떨어져요 | 첫 판 할인(설정값 `firstRunDiscount`, 지금 꺼짐)을 의뢰인과 정해요. 봇 측정값은 05 8.13 |
| 갈림길을 '새로워서'로만 골라요 | 갈림길 카드에 광맥마다 위험과 보상 한 줄을 더해요(보고서 5장) |

결과는 결정 기록에 한 줄씩 남기고 01·05 문서를 고쳐요.
