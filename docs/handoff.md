# 인수인계 문서

이 프로젝트를 이어받는 사람(나중의 나, 다른 개발자, Claude Code)이 처음 읽는 문서예요. 지금 어디까지 왔는지, 무엇으로 만들고 있는지, 어떻게 작업하는지, 다음에 무엇을 하면 되는지를 정리했어요.

마지막 갱신: 2026-11-23

## 1. 한 줄 소개

**One Candle Deep(원 캔들 딥)** 은 지뢰찾기 숫자 추리와 채굴 로그라이트를 합친 탑다운 2D 픽셀 게임이에요. 1인 개발(정해성)이고, 스팀(PC) 출시가 목표예요.

- 숫자는 둘레 8칸의 지뢰와 보물을 함께 세요. 층마다 바뀌는 광맥 규칙으로 둘을 가려내요.
- 한 판은 15일이에요. 광산 값을 도장 세 번(3일째 300, 8일째 2,400, 15일째 11,000)에 나눠 내고, 못 내면 판이 끝나요. 지금 프로토타입 기본 규칙(v2.2 시험)은 사흘마다 다섯 번(300 / 900 / 1,700 / 3,000 / 4,800)이에요.
- 하루는 촛불 80개예요. 바위를 한 번 칠 때마다 촛불 1개가 들어요. v2.2 시험에서는 촛불이 0이 되면 그 자리에서 하루가 끝나요.

한글 이름도 영어 이름을 소리 나는 대로 읽은 원 캔들 딥이에요. 옛 가제 「초 한 자루」는 1차 기록(docs/v1)에만 남아 있어요.

## 3. 스택

### 3.1 지금: 웹 프로토타입 (M0)

규칙과 재미, 경제 숫자를 빨리 고치고 재는 작업대예요.

| 구성 | 쓰임 |
|---|---|
| JavaScript ES 모듈 | 게임 코드. 규칙(`core.js`)과 화면(`ui.js`)이 나뉘어 있어요 |
| Vite | 개발 서버, 빌드. 빌드 결과는 HTML 파일 하나예요(vite-plugin-singlefile) |
| TypeScript | 타입 검사. 기존 코드는 JavaScript 그대로 두고, 타입 선언 파일(`.d.ts`)로 바깥 모양만 적어 뒀어요 |
| Vitest | 테스트 |
| tsx | 봇 경제 측정 보고서(`bot/cli.ts`) 실행 |

Node.js 20 이상이 필요해요.

### 3.2 다음: Godot 4 (M1부터)

스팀판은 Godot 4로 다시 만들어요. 웹 프로토타입을 그대로 스팀에 내지 않는 이유는 이래요.

- 웹 화면 코드는 시험용이에요. 연출, 해상도 대응, 스팀덱 대응을 넣으려면 어차피 새로 짜야 해요.
- Godot은 윈도우·맥·리눅스 실행 파일을 바로 만들고, 스팀 연동 플러그인(GodotSteam)이 있어요. 무료(MIT)예요.

웹 프로토타입은 Godot으로 옮긴 뒤에도 계속 써요.

- **규칙 정답지:** Godot으로 옮긴 규칙이 맞는지, 같은 씨앗을 넣어 웹 쪽과 같은 층·같은 결과가 나오는지 비교해요.
- **경제 측정:** 수치 조정은 웹 쪽 봇으로 먼저 재고, 확정된 값만 Godot에 넣어요.
- **데모:** 빌드 결과가 파일 하나라 웹에 올려 먼저 시켜 볼 수 있어요.

손맛(연출, 소리, 화면 흔들림, 애니메이션 타이밍)은 웹에서 다듬지 않고 Godot에서 맞춰요. 그래서 웹 화면은 "알아볼 수 있고 시험할 수 있는" 정도면 충분해요.

## 5. 코드 구조

- **규칙은 `prototype/src/core.js` 한 곳에만 있어요.** 화면, 봇, 테스트가 모두 이 모듈을 `import`해요. DOM을 쓰지 않아서 Node에서도 돌아가요.
- 수치는 `core.js`의 `CONFIG`에 모여 있어요. 기준 값은 [05_items_economy.md](05_items_economy.md)예요.
- 화면(`ui.js`)은 규칙 모듈을 불러 그리기만 해요.
- 봇(`bot/bot.js`)은 정책 세 가지(신중, 보통, 욕심)로 한 판을 끝까지 둬요. 다른 스크립트에서 쓰려면 이렇게 해요.

  ```ts
  import { load, playRun } from './bot/bot.js';
  const env = load();
  const result = playRun(env, 1001, { policy: 'normal' }); // 'cautious' | 'normal' | 'greedy'
  console.log(result.final);
  ```

  `load()`는 규칙 모듈 하나를 같이 써요. 그래서 `CONFIG`를 고치면 같은 프로세스의 다음 판에도 남아요.
- 판 생성은 씨앗(seed)으로 정해져요. 같은 씨앗이면 같은 층, 같은 봇 결과가 나와요.
- 새 코드는 TypeScript로 써요. 기존 JavaScript는 `src/core.d.ts`의 타입을 조금씩 좁혀 가며 검사를 늘려요.

## 6. 작업 규칙

### 화면과 문구
- 조작은 마우스 중심이에요. 화면에 키 안내를 띄우지 않고, 키보드 단축키는 설정 안에만 있어요.
- 게임 안 설명 문구는 전부 해요체예요. '~음', '~함', '~다'로 끝나는 설명은 쓰지 않아요. 인물이 직접 말하는 대사만 인물 말투예요. 문구 기준은 [02_narrative.md](02_narrative.md)예요.
- 화면에서는 계약금·중도금·잔금 대신 '도장'이라고 써요.
- 화면 문구와 문서에 내부 코드(결정 번호, 함수 이름)를 쓰지 않아요. 이모지도 쓰지 않아요.
- 브라우저 기본 alert / confirm / prompt 를 쓰지 않아요. 확인 창은 화면 안에 직접 그려요. localStorage는 try/catch로 감싸요.

### 규칙과 수치를 바꿀 때
1. `prototype/src/core.js`를 고쳐요.
2. `npm test`로 생성기와 규칙이 깨지지 않았는지 봐요.
3. 경제 수치(납부액, 보물 값, 시세, 도구 값)를 바꿨다면 `npm run bot`으로 다시 재요.
4. [decisions.md](decisions.md)에 결정 한 줄을 남겨요.
5. 관련 문서(01, 02, 03, 05, 06, 07)를 같이 맞춰요. 경제 수치는 05가 기준이에요.

### 명령어 (`prototype/` 안에서)

| 명령 | 하는 일 |
|---|---|
| `npm install` | 처음 한 번 |
| `npm run dev` | 개발 서버(http://localhost:5173) |
| `npm test` | 테스트(30초 안팎) |
| `npm run typecheck` | 타입 검사 |
| `npm run bot` | 경제 측정 보고서(1~2분). `npm run bot -- 300`처럼 판 수를 줄 수 있어요 |
| `npm run build` | `dist/index.html` 파일 하나로 빌드 |

디버그 키: F2 판 공개, F3 촛불 가득, F4 금고 +500, F8 오늘 끝, F9 하루 넘김.

GitHub에 올리면 `.github/workflows/ci.yml`이 푸시마다 타입 검사, 테스트, 빌드를 돌려요.
